# ADN Planner (раньше Planner A1)

Личный планировщик и трекер целей для телефона, планшета и компьютера. Один файл `index.html` (HTML + CSS + JS без сборки и зависимостей). Владелец проекта не программист, поэтому объясняйте простым языком и показывайте результат, а не код. Язык общения: русский.

Идея на будущее: встроенный ИИ-агент, который подсказывает по эффективности и дисциплине, настоящие аккаунты и вход, интеграции (Worksection, Garmin).

## Две версии из одного файла
- **claude.ai Artifact** (`window.claude` есть): облако через `claude.use('db'/'user')`, календарь через `mcp`, выгрузка файла через `downloads`.
- **Сайт / приложение (PWA)** на GitHub Pages: https://adintsove.github.io/planner/ (`WEB=true`). Вход через Google (Firebase Auth, compat SDK с gstatic, `FBV`), облако — Firestore с теми же путями `data/users/<uid>/sync/{p,c}` (код `synStart(db,id)` общий), календарь — Google Calendar REST (`gcRest`, токен через Google Identity Services, `GC_CLIENT`, токен ~1 ч, при истечении нужно нажать «Синхронизировать»). Настройки `FB_CFG` и `GC_CLIENT` в начале скрипта (не секрет; доступ защищают правила Firestore: `match /data/users/{uid}/{rest=**}` только для `request.auth.uid == uid`).
- Установка: `manifest.webmanifest`, `sw.js` (страница — сеть, затем кэш; firebase/шрифты — кэш), значки в `icons/`. Экран входа `#wlc` (можно «Продолжить без входа», `planner-skiplogin`), карточки «Аккаунт», «Установить приложение», «Перенос данных» (выгрузка/загрузка JSON, перед загрузкой `snapTake(true)`).

## Как сейчас публикуется
- Приложение публикуется как приватный Artifact на claude.ai (ссылка: https://claude.ai/artifact/NZ6unpRNK9eqYYFyk6d8mR), версия на момент переноса: 66, после защиты синхронизации: 67.
- Возможности Artifact: `db` и `user` (облачная синхронизация между устройствами), `mcp` (Google Calendar: list_calendars, list_events, create_event, update_event, delete_event) и `downloads` (выгрузка данных в файл).
- Сайт обновляется сам: GitHub Pages публикует ветку `main`.
- Источник правды теперь этот репозиторий (`index.html`). После правок файл публикуется в тот же Artifact.
- Тесты: Playwright (Chromium) с подменой `window.claude` (`claude.use('db'|'user'|'mcp')`) и `SpeechRecognition`; перед публикацией скрипт вынимается из `<script>` и проверяется `node --check`.

## Данные
Состояние `S` хранится в localStorage (`planner-v1`) через `save()`:
`spheres, goals, tasks, done['id|YYYY-MM-DD'], zones, bag, notes[day], wake, bed, life, theme, lang, sync, gcal`.
- `tasks`: `{id,title,sphere,start,dur,date,repeat,days,until,goal,fromBag,gsrc}`.
- `bag` (шарики): `{id,title,sphere,imp,tid,goal,focus,due,cr,gsrc}`. `due` и `cr` задают кольцо-таймер (от момента создания/начала до конца дня срока). `focus` — шарик в шаре «Супер-фокус» (до 5 штук, `FOCUS`; радиус шара `FR=W*0.23`, шарики внутри не больше `FR/2.75`).
- `notes[day]`: `{h (html), d (png dataURL рисунка), lh (логическая высота поля), im (картинки), sk (стикеры)}`.
- `sk` (стикеры): `{x,y,w,h,c (цвет), fs (размер текста, логический, по умолчанию 22; шаги `SKF`), t (html текста), d (png рисунка на стикере), cw,ch (размер холста стикера)}`; координаты логические (ширина поля 800).

## Основные модули в index.html
- i18n (ru/en/pl/uk): словарь `DICT` + `RX`, функция `tr()`, MutationObserver; каждая новая строка интерфейса требует записи в `DICT`.
- Облачная синхронизация (`db`): куски `main` и `n-<день>`, хеш `hsh`, разрешение конфликтов «последний победил» по `S.sync.mt`, локальная копия перезаписанного куска в `planner-backup-<key>`.
- Резервные копии: до 12 снимков в localStorage (`planner-snap-<ts>`), восстановление в Настройках.
- Google Календарь (`gcSync`): двусторонне для задач приложения (связки `S.gcal.map`), события Google с временем приходят как задачи (`imp`), многодневные события приходят шариками в мешок с таймером, остальные показываются серым. Свои события узнаются по описанию «Создано в приложении «ADN Planner»» (раньше «Planner A1» и «Розвиватор A1» — старые метки тоже узнаются). Есть защита от дублей, лимит 30 операций за запуск, пауза 45 минут при ошибке квоты Google. Приложение никогда не удаляет задачи из-за пропажи события с первого раза.
- Защита от «эха» (v79): задачи из Google (`gsrc`) никогда не отправляются в Google как новые — без связки они привязываются к исходному событию (тот же заголовок/дата/время, не `app`). Уже созданные копии (событие приложения, точно повторяющее чужое событие) удаляются из Google, лишние задачи (две на одно событие) убираются со снимком `snapTake(true)`. При переносе события в задачу сначала ищется такая же существующая задача.
- Заметки со стилусом: canvas поверх contenteditable, режим «Только стилус» (палец только прокручивает), защита от касаний ладони, клетка на фоне, кнопка «Растянуть поле», асинхронное сохранение.
- Голосовые задачи: кнопка микрофона (Web Speech API), разбор даты, времени и длительности для ru/uk/pl/en.
- Колёса выбора времени и длительности, цитата дня (200 цитат), эффективность дня (кольца).

## Шар «Супер-фокус» в Ежедневнике (v74)
- В правом верхнем углу календаря (`.calw` > `#ffw`, `position:sticky`) маленький шар как в мешке: до 5 цветных шариков с названиями (раскладка `FFL`, размеры `FFD`), плавает, пока виден календарь.
- Нажатие на шарик открывает его окно (`openBall`); перетаскивание шарика на сетку дня/недели планирует задачу на это время (шаг 15 мин, `ffSlot`/`ffSched`, подсветка `#ffpv`, всплывашка «Запланировано: …»), в месяце — на день в 09:00. Уже запланированный шарик бледный, с временем; перетаскивание переносит его задачу.
- Нажатие на фон шара сворачивает его в кружок ★ с числом (`FF.min`, `localStorage planner-ffmin`); пустой фокус — бледная ★, ведёт в мешок.

## Защита синхронизации (v67)
- Пустой/кэшированный первый ответ облака не считается готовой синхронизацией; пустое `main` без известного прошлого не отправляется.
- Отправка `main` блокируется, если задач+шариков+целей стало меньше 40% от известного в облаке (баннер «Отправить всё равно» / «Восстановить из облака»), перед этим делается снимок.
- Пустое `main` из облака не применяется, если локально данные есть: облако восстанавливается из локальных данных.
- В `p/main` хранится счётчик `c`; облачная копия последнего здорового состояния — `c/bak~i` и `c/bakm` (не чаще раза в 30 мин), кнопка в Настройках → «Резервные копии».

## Рисование в заметках (v68+)
- Холст обновляется только вокруг штриха (`base` — теневая копия, undo хранит заплатки `{r,c}`), штрих сглаживается, нажим сглаживается.
- Защита от ладони: широкое касание игнорируется; когда перо коснулось, все касания сбрасываются; палец начинает прокрутку только после сдвига на 8 px; нажатия на панель инструментов пальцем во время письма игнорируются; на iPad по умолчанию «Только стилус».
- Во время письма не делаются перерисовка страницы (`softRender`) и автосохранение рисунка (ждём 3 с после пера).

## Стикеры в заметках (v70)
- Кнопка «Добавить стикер» на панели заметок. Стикер лежит в слое `#nstks` поверх рисунка страницы.
- Режим «Текст»: печать на стикере, перетаскивание за верхнюю полоску, угол меняет размер, над выделенным стикером — цвета, размер текста (A− / A+) и удаление.
- Режим «Рисование»: штрих, начатый на стикере, рисуется на холсте стикера (движок штрихов работает с «поверхностью» `s.g`: `M` — страница или стикер). Холст стикера только растёт, чтобы не терять рисунок при уменьшении.

## Принципы
- Не терять данные пользователя: любые автоматические удаления только после повторной проверки, перед рискованными операциями делать снимок (`snapTake(true)`).
- Не вставлять секреты (ключи, client secret) в этот файл: страница публична для всех, у кого есть код.
- Сначала понятный результат для пользователя, потом детали.
